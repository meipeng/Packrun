## 3. 路由

路由定义：[router/index.ts](../../web/src/router/index.ts)

| 路径 | 名称 | 组件 | 角色限制 |
|---|---|---|---|
| `/login` | login | `LoginView` | 公开 |
| `/` | overview | `OverviewView` | 登录 |
| `/projects` | projects | `ProjectsView` | admin / deployer |
| `/servers` | servers | `ServersView` | 登录 |
| `/deploy` | deploy | `DeployWizardView` | admin / deployer |
| `/tasks` | tasks | `TasksView` | 登录 |
| `/tasks/:id` | task-detail | `TaskDetailView` | 登录 |
| `/scripts` | scripts | `ScriptsView` | 登录 |
| `/audit` | audit | `AuditView` | admin / auditor |
| `/users` | users | `UsersView` | admin |
| `/profile` | profile | `ProfileView` | 登录 |
| `/:pathMatch(.*)*` | — | 重定向 `/` | — |

守卫逻辑：

1. `meta.public` 直接放行；
2. 无 token → 跳登录并携带 `redirect`；
3. 有 token 但无用户 → `auth.fetchMe()`，失败则登出；
4. `meta.roles` 存在且当前角色不在其中 → 跳概览；
5. 其余放行。

前端路由限制只是体验层；真正的权限校验在后端。

## 4. 状态管理

文件：[stores/auth.ts](../../web/src/stores/auth.ts)

| 成员 | 说明 |
|---|---|
| `token` | 初始值来自 `localStorage.packrun_token` |
| `user` | 当前用户对象，初始为 `null` |
| `isAdmin` | `role === 'admin'` |
| `isAuditor` | `role === 'auditor'` |
| `canDeploy` | 已登录且角色不是 `auditor` |
| `displayName` | `displayName || username` |
| `login(payload)` | 调用登录接口，保存 token 与 user 到内存/localStorage |
| `fetchMe()` | 拉取当前用户 |
| `logout()` | 清空内存与 localStorage |

没有 refresh token 机制；令牌过期后由 axios 拦截器跳登录。

## 5. HTTP 层

文件：[api/http.ts](../../web/src/api/http.ts)

```ts
const basePath = appBasePath()
const http = axios.create({
  baseURL: `${basePath}api/v1`,
  timeout: 60000,
})
```

请求拦截器：

- 从 `localStorage.packrun_token` 读取令牌；
- 注入 `Authorization: Bearer <token>`。

响应拦截器：

- 业务成功：直接返回 `body.data`，调用方拿到的就是数据本身；
- 业务失败（`code !== 0`）：抛出带 `code` 的 `Error`；
- HTTP 错误：
  - 401 且 `code` 不是 `1428`/`1003` → 清除 token 并跳转 `${basePath}login`；
  - 其他错误保留 `message`、`code`、`status`。

`1428`（需要动态口令）与 `1003`（动态口令错误）不跳登录，交给页面继续交互。

## 6. 子路径部署

文件：[utils/base.ts](../../web/src/utils/base.ts)

```ts
export function appBasePath(): string {
  const href = document.querySelector('base')?.getAttribute('href') || '/'
  return href.endsWith('/') ? href : `${href}/`
}
```

- 构建时 Vite `base: './'`，资源使用相对路径；
- 运行时服务端把 `index.html` 的 `<base href>` 替换为实际子路径；
- 路由 `createWebHistory(appBasePath())`；
- axios `baseURL` 使用同一前缀；
- 因此同一份构建可部署在 `/` 或 `/packrun/` 等任意子路径。

## 9. 页面职责

### 9.1 登录 `LoginView.vue`

- 账号 + 口令；需要时显示 OTP 输入框；
- 支持切换「动态口令 / 恢复码」输入；
- 登录失败且 `code` 为 `1428` 或 `1003` 时自动展开 OTP 输入并聚焦；
- 成功后跳转 `redirect` 或首页。

### 9.2 概览 `OverviewView.vue`

- 四个统计卡片：中控机状态（版本/运行时长）、包仓库占用、磁盘剩余、纳管服务器；
- 健康检查明细：数据库、包仓库、磁盘、近期任务四项，含状态标签、详情与耗时；
  任一硬性检查失败时展示错误提示（对应 `/healthz` 的 503）；
- 服务器资源表：状态、负载、内存、根分区磁盘、采集时间；
- 30 秒自动刷新，页头提供手动刷新；「发起部署」按钮仅 `canDeploy` 可见。

### 9.3 部署向导 `DeployWizardView.vue`

三步：

1. **选择目标**：服务器卡片（环境标签、在线状态、内存/磁盘摘要、指纹已登记标记）；
   选中后加载该服务器目录，展示覆盖/备份/保留策略。
2. **上传安装包**：拖拽/点选 zip/jar，前端校验扩展名与 200MB 上限，
   上传进度，成功后自动选中；也可从最近上传中选择。
3. **脚本与确认**：选择 `precheck` 与 `postdeploy` 脚本，预览摘要；
   生产环境显示 6 位 OTP 输入。

提交调用 `taskApi.create`，成功后跳转 `/tasks/:id`。

### 9.4 项目工作台 `ProjectsView.vue`

- 左侧项目列表（名称 + 当前版本）；非管理员只显示被授权项目；
- 主区：项目名称/标识/版本、成员标签、项目设置按钮；
- 更新目录卡片：展示服务器、环境、备份/覆盖策略；
- 部署空间：拖入 zip/jar 或选择最近上传的包；
- 发布：若有 `prod` 目录，弹出 OTP 输入；文件模式会先上传再发布；
- 历史：按批次展示，进行中批次每 1.5 秒轮询；
- 回滚：仅成功批次可回滚，且版本不能等于当前版本；
- 项目设置：目录绑定所有可管理成员可改；成员与发布策略仅管理员可见/可提交。

### 9.5 服务器 `ServersView.vue`

- 服务器表格：名称、环境、地址、状态、并发、指纹、备注；
- 新增/编辑对话框：名称、环境、主机、端口、用户、认证方式、凭据引用、并发、备注；
- 检测：`probe` 采集指标并展示凭据自检信息；
- 指纹对话框：采集当前指纹、显示是否已登记/匹配、清除指纹；
- 目录抽屉：新增/编辑/删除该服务器的部署目录。

### 9.6 任务列表 `TasksView.vue`

- 关键字（任务号/包名/操作人）与状态筛选；
- 分页表格，展示任务号、服务器与目录、状态、进度、操作人、耗时；
- 行点击进入任务详情。

### 9.7 任务详情 `TaskDetailView.vue`

- 运行中每 2 秒轮询 `taskApi.get`；
- 任务信息：服务器、操作人、目录、包、前置/后置脚本、OTP 校验、耗时、创建时间；
- 进度条：`stage + progress`；
- 执行步骤时间线：步骤状态与日志输出；
- 运行中且 `canDeploy` 时显示取消按钮。

### 9.8 脚本 `ScriptsView.vue`

- 脚本列表：名称、阶段、超时、执行身份、版本、描述；
- 新增/编辑对话框：名称、阶段、内容、超时、`runAs`、描述；
- 删除确认。

### 9.9 审计 `AuditView.vue`

- 动作、操作者、关键字筛选；
- 动作枚举映射为中文标签（登录、改密、任务创建/结束/取消、配置变更等）；
- 表格展示时间、操作者、动作、目标、结果、IP、任务号、OTP 校验、细节。

### 9.10 用户 `UsersView.vue`

- 用户列表：账号、展示名、角色、状态、数据范围、归属主账号、项目；
- 新增/编辑：账号、展示名、初始口令、角色、`serverScope`、`parentId`、授权项目、状态；
- 管理员可在「授权项目」中直接勾选子账户可见的项目（复用项目成员关系）；
- 项目标签由项目成员关系反推；
- 「最后一个启用管理员」由后端保护，前端只展示错误。

### 9.11 个人设置 `ProfileView.vue`

- 修改口令（已绑定 OTP 时必须输入当前 OTP）；
- 绑定动态口令：展示二维码（`qrcode.vue`）与手动种子，输入 6 位口令启用；
- 绑定成功后展示 10 枚恢复码（仅一次），支持复制；
- 换绑：输入旧 OTP → 展示新二维码 → 输入新 OTP 确认；
- 解绑：输入当前 OTP 并二次确认；
- 恢复码状态：总数/剩余，可重新生成（旧码立即失效）。

## 11. 开发与构建

```bash
cd web
pnpm install
pnpm dev        # http://localhost:5173，/api 补 /packrun 前缀后与 /healthz 代理到 127.0.0.1:9000
pnpm build      # 产物 web/dist
pnpm type-check # vue-tsc --noEmit
```

Vite 配置：[vite.config.ts](../../web/vite.config.ts)

- `base: './'`；
- 别名 `@` → `src`；
- 开发代理：`/api` 重写为 `/packrun/api` 后转发、`/healthz` 直接转发到 `http://127.0.0.1:9000`。

生产构建由根目录 `make build` 调用 `pnpm build`，然后把 `web/dist` 同步到
`server/internal/webui/dist` 并嵌入 Go 二进制。

## 12. 新增页面清单

1. 在 `web/src/views/` 新建 `XxxView.vue`；
2. 在 `router/index.ts` 增加路由与 `meta.title` / `meta.roles`；
3. 如需菜单入口，在 `AppLayout.vue` 的 `menu` 数组增加项；
4. 在 `api/index.ts` 增加接口函数与类型；
5. 如需后端接口，按 [03-后端模块与关键函数](03-后端模块与关键函数.md) 在 `internal/api`
   增加处理器并注册路由；
6. 运行 `pnpm type-check` 与 `pnpm build`。

## 13. 前端注意点

| 项 | 说明 |
|---|---|
| 令牌存储 | `localStorage`，XSS 可读取；依赖 CSP 与代码审查降低风险 |
| 无刷新令牌 | 过期后直接跳登录 |
| 轮询 | 项目历史 1.5 秒、任务详情 2 秒；离开页面时清理定时器 |
| 前端校验 | 扩展名、大小、OTP 长度等只是体验层，后端独立校验 |
| 错误提示 | axios 已解包 `message`，页面统一 `ElMessage.error(e.message)` |
| 非管理员项目页 | 拉取用户列表会 403，代码中已忽略 |
| 子路径 | 不要硬编码 `/api` 或绝对资源路径，统一使用 `appBasePath()` 与相对资源 |
