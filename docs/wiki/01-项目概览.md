# 01 项目概览

## 1. 项目定位

Packrun 解决的是「把构建产物稳定地放到业务服务器指定目录，并留下可追溯记录」这件事。
它不负责源码构建，也不依赖 CI/CD 平台；核心是一个部署在中控机的 Go 服务：

- 中控机是唯一对外暴露点，业务服务器不需要对公网开放；
- 所有目标服务器、目录策略、脚本、安装包与任务记录集中管理；
- 浏览器端提供完整的部署控制台，前端构建产物可嵌入 Go 二进制，单文件交付；
- 执行通道抽象为 `Deployer` 接口，当前提供 `local`（本地沙箱）与 `ssh`（远程执行）两种实现；
- 生产环境部署强制动态口令（TOTP）再认证，全链路写审计日志。

## 2. 核心能力

| 能力 | 说明 | 入口 |
|---|---|---|
| 服务器纳管 | 记录主机、端口、用户、认证方式、凭据引用、并发上限、环境标签 | `servers` 表 / 服务器页 |
| 主机指纹 TOFU | 首次 SSH 连接自动登记主机指纹，之后严格校验；支持检测与清除 | `SSHDeployer.hostKeyCallbackFor` |
| 目录策略 | 绝对路径校验、覆盖开关、部署前备份、保留版本数、空间阈值 | `directories` 表 / 服务器页目录抽屉 |
| 安装包仓库 | zip/jar 上传、文件头校验、SHA256 登记、总容量配额 | `packages` 表 / 部署向导 |
| 脚本管理 | 前置校验 `precheck` 与部署后 `postdeploy` 脚本、超时、执行身份、版本递增 | `scripts` 表 / 脚本页 |
| 单目标部署 | 通过部署向导选择服务器/目录/包/脚本并发起任务 | `POST /api/v1/tasks` |
| 项目工作台 | 一个项目绑定多个目录，一次发布同包更新全部目录，按批次聚合历史 | `projects` 相关接口 |
| 历史回滚 | 选择历史成功批次，复用其安装包重新发布到全部绑定目录 | `POST /api/v1/projects/:id/rollback` |
| 任务与日志 | 任务状态机、步骤时间线、每步输出、耗时、失败原因 | `tasks` / `task_steps` |
| 运行指标 | 定时/手动通过 SSH 采集负载、内存、磁盘、主机信息 | `ServerMetric` / 指标采集器 |
| 审计 | 登录、配置变更、任务创建/结束、取消、重启收口等事件 | `audit_logs` 表 / 审计页 |
| 权限模型 | 管理员 / 发布者 / 审计员；服务器数据范围 `serverScope`；项目成员授权 | `App.scopeServerIDs` 等 |
| 双因子认证 | bcrypt 口令 + TOTP；10 枚一次性恢复码；改密与高危操作再认证 | `internal/auth`、`auth_api.go` |

## 3. 技术栈

### 3.1 后端

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.26（`server/go.mod`） | 单二进制、无运行时依赖 |
| HTTP | Gin v1.10 | 路由分组、中间件 |
| ORM | GORM v1.25 | 自动迁移 `AutoMigrate` |
| 数据库 | `glebarez/sqlite`（纯 Go SQLite） | 免 CGO，适合单机中控；WAL 模式 |
| 认证 | `golang-jwt/jwt/v5`（HS256）+ `x/crypto/bcrypt` | 无状态会话 + 口令哈希 |
| 动态口令 | 自实现 TOTP（HMAC-SHA1，6 位，30 秒） | 种子 base32，支持 ±skew 时间窗 |
| 执行通道 | `golang.org/x/crypto/ssh` | SSH 远程执行、`knownhosts` 回退校验 |
| 配置 | `gopkg.in/yaml.v3` + 环境变量覆盖 | 单文件配置 |
| 前端托管 | `go:embed` + `net/http` 文件服务 | 单二进制内嵌前端 |

### 3.2 前端

| 领域 | 选型 |
|---|---|
| 框架 | Vue 3.5（`<script setup>` + TypeScript） |
| 构建 | Vite 6 |
| UI | Element Plus 2.9 + `@element-plus/icons-vue` |
| 状态 | Pinia 2 |
| 路由 | Vue Router 4（History 模式） |
| 请求 | axios（统一拦截器） |
| 其他 | `qrcode.vue`（动态口令二维码）、`dayjs` |

### 3.3 构建与交付

- `make build`：构建前端 → 同步到 `server/internal/webui/dist` → `go build` 生成
  `server/bin/packrund`（前端已内嵌）。
- `make package`：交叉编译（默认 `linux/amd64`）并打包 `dist/packrun-linux-amd64.tar.gz`。
- `start.sh`：后台/前台启动、停止、状态、日志、打印 Nginx 子路径配置。
- `deploy/`：Nginx 与 frp 配置样例。

## 4. 角色与典型流程

### 4.1 角色

| 角色 | 常量 | 权限概述 |
|---|---|---|
| 管理员 | `admin` | 全部权限：服务器/目录/脚本/用户配置、发布、回滚、审计 |
| 发布者 | `deployer` | 在授权服务器范围内发起部署、发布、回滚、取消任务；不可改全局配置 |
| 审计员 | `auditor` | 只读；可查看服务器/任务/项目/审计，不可发起部署、取消任务、上传包、创建项目。当前实现允许对范围内服务器执行连通性/指标/指纹检测 |

后端不依赖前端做权限控制：每个高危操作在处理函数内独立校验角色、数据范围与动态口令。

### 4.2 单目标部署流程

```
登录（口令 [+ TOTP]）
  → 部署向导：选服务器 → 选目录 → 上传 zip/jar → 选前置/后置脚本
  → 生产环境输入 TOTP（step-up）
  → 创建任务（pending）
  → 后台 goroutine 排队（目录锁 → 服务器闸门 → 全局闸门）
  → 执行器按步骤执行并回写 task_steps / progress
  → success / failed / canceled
  → 写 task.finish 审计；项目批次则结算版本
```

### 4.3 项目批量发布流程

```
项目设置：绑定多个部署目录 + 成员 + 发布策略
  → 拖入/选择安装包
  → 一次发布为每个绑定目录创建同批次任务（BatchNo）
  → 批次内任务全部成功 → 项目版本推进到该批次版本
  → 历史按 BatchNo 聚合，可对成功批次发起回滚
```

## 5. 仓库目录结构

```
Packrun/
├── server/                        Go 中控服务
│   ├── cmd/packrund/main.go       进程入口：装配配置、存储、执行器、路由
│   ├── configs/config.yaml        配置样例
│   ├── data/                      运行期数据（SQLite、包仓库、沙箱、日志）
│   ├── bin/packrund               单文件构建产物（make build 生成）
│   └── internal/
│       ├── config/                配置加载、校验、环境变量覆盖
│       ├── model/                 全部 GORM 实体与状态常量
│       ├── store/                 SQLite 打开、迁移、初始数据
│       ├── auth/                  bcrypt、JWT、TOTP、恢复码
│       ├── deploy/                执行器抽象、local/ssh 实现、指标、主机指纹
│       ├── api/                   路由、中间件、处理器、任务编排、静态托管
│       └── webui/                 内嵌前端构建产物（go:embed）
├── web/                           Vue 3 + Vite 控制台
│   └── src/{api,stores,router,layouts,views,utils,styles}
├── deploy/                        Nginx / frps / frpc 配置样例
├── docs/                          设计与部署文档
├── Makefile                       构建与打包入口
└── start.sh                       启动脚本
```

## 6. 术语表

| 术语 | 含义 |
|---|---|
| 中控机 | 运行 `packrund` 的机器，持有数据库、包仓库与 SSH 凭据引用 |
| 业务服务器 | 部署目标机，只需中控机可达 |
| 执行器（Deployer） | 把包推送到目标目录并执行脚本的抽象；`local` 或 `ssh` |
| 部署目录 | 业务服务器上的绝对路径目标，带覆盖/备份/空间策略 |
| 任务（Task） | 一次单目录部署的执行记录，状态机 + 步骤日志 |
| 批次（BatchNo） | 项目一次发布产生的多条任务，聚合为一条历史记录与一个项目版本 |
| 发布（publish） | 项目工作台批量部署，版本号自动递增 |
| 回滚（rollback） | 复用历史成功批次的安装包，重新发布到当前绑定目录 |
| step-up | 高危操作前的动态口令再认证 |
| TOFU | Trust On First Use，首次连接自动信任并登记主机指纹 |
| 生产环境 | 服务器实体上的 `env=prod`，触发强制 TOTP 校验 |
| 本地沙箱 | `deploy.mode=local`，真实落盘/解包但不执行脚本 |

## 7. 两种执行模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `local` | 目标路径映射到 `data/sandbox/<服务器名>/<目录>`；真实写包、校验 SHA256、解包；脚本只渲染回显不执行 | 本地开发、演示、UI 联调 |
| `ssh` | 通过 SSH 连接目标机：`cat > /tmp/...` 上传、`sha256sum` 校验、`unzip`/`mv`、远程脚本执行、备份清理 | 生产 |

模式由 `deploy.mode` 或环境变量 `PACKRUN_DEPLOY_MODE` 决定，详见
[06-部署执行引擎](06-部署执行引擎.md)。
