# 09 构建运行与运维

## 1. 环境要求

| 环境 | 要求 |
|---|---|
| Go | 1.26+（`server/go.mod`）；仓库可用 `.tools/go` 内置工具链 |
| Node / pnpm | 构建前端需要；Vite 6 + pnpm |
| 数据库 | 无外部依赖，纯 Go SQLite |
| 目标机（SSH 模式） | `sh`、`unzip`、`zipinfo`、`sha256sum`、`timeout`、`base64`；按需 `sudo -n` |
| 端口 | 默认 `0.0.0.0:9000`（直连）；Nginx/frp 可选 |

前端构建产物会嵌入 Go 二进制，生产不需要单独部署前端静态文件。

## 2. 本地开发

### 2.1 后端

```bash
cd server
go run ./cmd/packrund -config configs/config.yaml
# 监听 0.0.0.0:9000
```

默认 `deploy.mode=ssh`。本地没有真实服务器时用沙箱模式：

```bash
PACKRUN_DEPLOY_MODE=local go run ./cmd/packrund -config configs/config.yaml
```

### 2.2 前端

```bash
cd web
pnpm install
pnpm dev
# http://localhost:5173
# /api 与 /healthz 代理到 127.0.0.1:9000
```

### 2.3 首次账号

| 账号 | 口令 | 说明 |
|---|---|---|
| `admin` | `Admin@12345` | 空库首次启动创建 |
| `auditor` | `Audit@12345` | 仅 `debug` 模式创建 |

`PACKRUN_ADMIN_PASSWORD` 只在空库首次初始化时生效，不是密码重置手段。

## 3. Build 与打包

### 3.1 Makefile

文件：[Makefile](../../Makefile)

| 目标 | 行为 |
|---|---|
| `make web` | `cd web && pnpm install --frozen-lockfile && pnpm build` |
| `make sync-web` | 清空 `server/internal/webui/dist` 后复制 `web/dist` |
| `make build` | `web` + `sync-web` + `CGO_ENABLED=0 go build -trimpath -o bin/packrund ./cmd/packrund` |
| `make package` | 构建并打包 `dist/packrun-linux-amd64.tar.gz` |
| `make clean` | 删除二进制、`dist/` 与嵌入产物（保留 `.gitkeep`） |

工具链选择：

- 优先使用 `PATH` 中的 `go`；
- 否则回退到 `.tools/go/bin/go`，并固定 `GOROOT`、`GOMODCACHE`、`GOPATH`。

交叉编译：

```bash
GOOS=linux GOARCH=amd64 make build
PKG_GOARCH=arm64 make package
```

产物：

- `server/bin/packrund`：单文件，前端已内嵌；
- `dist/packrun-<os>-<arch>.tar.gz`：包含二进制、`config.yaml`、`start.sh`、`deploy/` 样例。

## 4. start.sh

文件：[start.sh](../../start.sh)

```bash
./start.sh                 # 后台启动（nohup，PID/日志在 server/data/）
./start.sh --stop          # 停止
./start.sh --status        # 状态
./start.sh --log           # tail -f 日志
./start.sh --foreground    # 前台启动，交给 systemd/supervisor
./start.sh --print-nginx   # 按当前子路径打印 Nginx location
```

启动前会：

- 校验二进制存在；
- 导出 `PACKRUN_ADDR`、`PACKRUN_DEPLOY_MODE`，按需导出 `PACKRUN_BASE_PATH`、
  `PACKRUN_JWT_SECRET`、`PACKRUN_ADMIN_PASSWORD`、`PACKRUN_MAX_CONCURRENT`；
- `cd` 到 `server/`，保证配置中的 `./data/...` 相对路径落在 `server/` 下。

脚本顶部可直接修改：

| 变量 | 默认值 |
|---|---|
| `PACKRUN_BIN` | `$APP_ROOT/server/bin/packrund` |
| `PACKRUN_CONFIG` | `$APP_ROOT/server/configs/config.yaml` |
| `PACKRUN_ADDR` | `0.0.0.0:9000` |
| `PACKRUN_BASE_PATH` | `/packrun` |
| `PACKRUN_DEPLOY_MODE` | `ssh` |
| `PACKRUN_JWT_SECRET` | 空 |
| `PACKRUN_ADMIN_PASSWORD` | 空 |
| `PACKRUN_MAX_CONCURRENT` | 空 |
| `NGINX_UPSTREAM` | 根据监听地址推导，默认 `http://127.0.0.1:9000` |

后台模式注意：交给 systemd 托管时必须用 `--foreground`，否则脚本会 nohup 到后台
导致 systemd 认为主进程退出。

## 5. 配置参考

加载优先级：**内置默认值 < YAML < 环境变量**。相对路径按进程当前工作目录解析，
systemd 部署必须固定 `WorkingDirectory`。

| 配置项 | 默认值 | 环境变量 | 说明 |
|---|---|---|---|
| `server.addr` | `0.0.0.0:9000` | `PACKRUN_ADDR` | 监听地址；直连时限制来源，前置代理时可改回 `127.0.0.1:9000` |
| `server.mode` | `debug` | — | `debug` / `release` / `test` |
| `server.base_path` | `/packrun` | `PACKRUN_BASE_PATH` | 对外子路径，默认 `/packrun`；根路径填 `/` |
| `server.allowed_origins` | `["http://localhost:5173"]` | — | CORS 白名单；release 禁止 `*` |
| `server.trusted_proxies` | `["127.0.0.1/32","::1/128"]` | — | 仅这些代理的转发头被采信 |
| `auth.jwt_secret` | dev 占位值 | `PACKRUN_JWT_SECRET` | HS256 密钥，release 要求 ≥32 字符 |
| `auth.token_ttl_minutes` | `480` | — | 令牌有效期 |
| `auth.otp_issuer` | `Packrun` | — | TOTP issuer |
| `auth.otp_period` | `30` | — | TOTP 周期（秒） |
| `auth.otp_skew` | `1` | — | 允许的时间窗偏移 |
| `storage.db_path` | `./data/packrun.db` | — | SQLite 主库 |
| `storage.package_dir` | `./data/packages` | — | 包仓库 |
| `storage.sandbox_root` | `./data/sandbox` | — | local 沙箱根目录 |
| `storage.max_total_mb` | `20480` | — | 包仓库容量上限；0 不限制 |
| `deploy.mode` | `ssh` | `PACKRUN_DEPLOY_MODE` | `local` / `ssh` |
| `deploy.max_concurrent` | `3` | `PACKRUN_MAX_CONCURRENT` | 全局并发；非正数回退 3 |
| `deploy.step_delay_ms` | `350` | — | 步骤间延迟；生产可设 0 |
| `deploy.max_pending_per_user` | `10` | — | 单用户未终态任务上限 |
| `deploy.metrics_interval_seconds` | `300` | — | 后台指标采集间隔；0 关闭 |
| `deploy.auto_trust_hostkey` | `true` | — | TOFU 首次自动信任 |
| `bootstrap.admin_username` | `admin` | — | 首次管理员账号 |
| `bootstrap.admin_password` | `Admin@12345` | `PACKRUN_ADMIN_PASSWORD` | 仅空库首次初始化 |

独立环境变量：

| 变量 | 说明 |
|---|---|
| `PACKRUN_SSH_INSECURE=1` | 跳过 SSH 主机指纹校验；仅 debug 允许 |
| `env:<VAR>` 凭据引用 | 服务器凭据引用的环境变量需注入 packrund 进程 |

## 6. 内置硬限制

| 项目 | 值 |
|---|---|
| 单包体积 | 200 MB，仅 `.zip` / `.jar`，校验文件头 |
| ZIP 条目数 | 20000 |
| ZIP 解包预算 | 目录 `maxSizeMB`，未配置时 1 GB |
| 非上传请求体 | 1 MiB |
| Multipart 内存 | 32 MiB |
| HTTP 超时 | ReadHeader 10s / Read 60s / Write 10min / Idle 120s |
| SSH 建连 | 10s |
| 单条远程命令 | 15min（指标采集 30s） |
| 脚本超时 | 默认 120s，可配 1-3600s |
| 登录失败锁定 | 同账号 5 次或同 IP 30 次 → 5 分钟 |
| step-up 失败锁定 | 5 次 → 5 分钟 |

注意：HTTP `ReadTimeout=60s` 且未豁免上传接口，弱网下接近 200MB 的包可能被
Go 侧先断开；前端 axios 总超时也是 60s。Nginx 的 600s 无法突破这一上限。

## 7. 生产启动约束

`server.mode=release`（或 `test`）时，以下任一不满足会拒绝启动：

1. JWT 密钥非空、非 dev 默认值、长度 ≥32；
2. 管理员口令非空且不等于 `Admin@12345`；
3. `allowed_origins` 不含 `*`；
4. `deploy.mode=ssh` 时 `PACKRUN_SSH_INSECURE` 未设置为 `1`；
5. 其他配置项通过格式与范围校验。

注意：release **不会**强制 `deploy.mode=ssh`，也不会强制监听回环，需要在配置中自行保证。

生成密钥：

```bash
openssl rand -hex 32   # JWT 密钥
openssl rand -hex 16   # frp token 同理
```

## 8. systemd 托管

假定安装根 `/opt/packrun`，运行账号 `packrun`：

```bash
mkdir -p /opt/packrun/server/{bin,configs}
install -m 0755 bin/packrund /opt/packrun/server/bin/packrund
install -m 0600 configs/config.yaml /opt/packrun/server/configs/config.yaml
useradd -r -s /usr/sbin/nologin packrun
chown -R packrun:packrun /opt/packrun
```

`/etc/packrun.env`（权限 600）：

```bash
PACKRUN_JWT_SECRET=<openssl rand -hex 32>
PACKRUN_ADMIN_PASSWORD=<首次初始化强口令>
PACKRUN_DEPLOY_MODE=ssh
# PROD_SSH_PASSWORD=xxx 等凭据变量也在此注入
```

`/etc/systemd/system/packrund.service`：

```ini
[Unit]
Description=Packrun 中控服务
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=packrun
Group=packrun
WorkingDirectory=/opt/packrun/server
ExecStart=/opt/packrun/server/bin/packrund -config /opt/packrun/server/configs/config.yaml
EnvironmentFile=/etc/packrun.env
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/packrun/server/data
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now packrund
journalctl -u packrund -f
```

## 9. Nginx 反代

单包模式可以跳过 Nginx，直接访问 `http://<中控机>:9000/packrun/`。需要域名/HTTPS 时，
Nginx 只做 TLS 终止与全站反代：

```nginx
location / {
    proxy_pass http://127.0.0.1:9000;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_request_buffering off;
    client_max_body_size 200m;
    proxy_send_timeout 600s;
    proxy_read_timeout 600s;
}
```

关键点：

- `client_max_body_size 200m`，与服务端 200MB 上限一致；注意它限制的是包含
  multipart 边界的整个请求体，贴近 200MB 的文件可能先被 Nginx 413；
- 关闭请求/响应缓冲，放宽超时；
- 登录接口单独限流（仓库样例 `deploy/nginx.conf.example` 中 `packrun_login` 为 5r/m）；
- `server.trusted_proxies` 必须与实际代理拓扑一致：
  - Nginx/frpc 与中控同机、18080 未对公网开放 → 可保留回环；
  - 否则清空，避免客户端伪造 `X-Forwarded-For` 绕过登录锁定与审计 IP。

### 9.1 子路径部署

默认子路径为 `/packrun`，`./start.sh --print-nginx` 会直接输出对应配置。如需改回根路径：

```bash
PACKRUN_BASE_PATH=/ ./start.sh
PACKRUN_BASE_PATH=/ ./start.sh --print-nginx
```

要点：

- 显式设置 `PACKRUN_BASE_PATH` 会覆盖 `config.yaml` 的 `server.base_path`，未设置时沿用配置文件；
- `proxy_pass` 不要带尾斜杠，保留 `/packrun/` 前缀交给应用处理；
- `location = /packrun` 需要 301 到 `/packrun/`；
- 应用会自动在 `index.html` 注入 `<base href="/packrun/">`，前端路由与 API
  前缀随之适配，无需重新构建；
- `/healthz` 始终保留在根路径，方便负载均衡探测。

## 10. frp 隧道

适用：中控机在内网，公网跳板机运行 frps。

`deploy/frps.toml` 要点：

- `proxyBindAddr = "127.0.0.1"`，18080 只监听回环；
- `auth.method = "token"`，token 替换为强随机值；
- `allowPorts = 18080-18089`；
- 公网只放行 80/443，18080 不得暴露。

`deploy/frpc.toml` 要点：

- `serverAddr` 指向 frps；
- token 与 frps 一致；
- 只映射 `localPort=9000` → `remotePort=18080`，不映射 SSH/数据库端口。

链路：`浏览器 → Nginx:443 → 127.0.0.1:18080 → frps → frpc → 127.0.0.1:9000 → packrund`。

## 11. 备份与恢复

数据库与包仓库是同一逻辑备份单元：数据库只存包的相对 `StorageKey`，只备份数据库
会导致历史发布与回滚失败。

### 11.1 离线备份（推荐）

```bash
systemctl stop packrund
tar -C /opt/packrun/server -czf /backup/packrun-$(date +%F).tar.gz \
    data/packrun.db data/packrun.db-wal data/packrun.db-shm \
    data/packages configs/config.yaml
```

另行保管：

- `/etc/packrun.env`；
- `file:` 引用的 SSH 私钥。

local 模式如需保留部署现场，追加 `data/sandbox`。

### 11.2 在线备份

不要直接复制运行中的主库文件。使用 SQLite 一致性备份：

```bash
sqlite3 /opt/packrun/server/data/packrun.db ".backup '/backup/packrun.db'"
# packages/ 仍需另行同步
```

### 11.3 恢复

1. 停止服务；
2. 恢复**同一代次**的数据库与 `packages/`；不要把旧 WAL/SHM 套到新主库上；
3. 恢复 env 与私钥；
4. 启动并按验收步骤检查。

### 11.4 部署备份 ≠ 数据备份

`<目录>.bak-YYYYmmddHHMMSS` 只是目标机上的旧版本（local 为改名，SSH 为 `cp -a`），
部署成功后按 `keepReleases` 清理；部署失败不会自动回滚；项目「回滚」是重新发布
历史安装包，与 `.bak-*` 无关。

## 12. 升级

1. 选择无任务窗口（重启会把未完成任务标记失败）；
2. 完成备份；
3. `make build` 生成新二进制；
4. `systemctl stop packrund`，替换二进制；
5. 启动；GORM 每次启动执行 `AutoMigrate`，没有独立迁移命令与降级流程，
   升级前备份是唯一回退手段；
6. 检查启动日志 `[recover]` 行，人工核对上次中断任务的目标目录是否残留半成品；
7. 重新验收；
8. 依赖升级后复跑 `govulncheck` 与 `pnpm audit --prod`；
9. 更换 `PACKRUN_JWT_SECRET` 会使所有已登录会话失效。

## 13. 验收与监控

### 13.1 上线验收

```bash
# 1. 进程存活
systemctl start packrund
journalctl -u packrund

# 2. 健康检查（仅存活探针，不检查 DB/SSH）
curl -fsS https://deploy.example.com/healthz
# {"status":"ok"}

# 3. 受保护接口要求认证
curl -sS -o /dev/null -w '%{http_code}\n' https://deploy.example.com/api/v1/auth/me
# 期望 401

# 4. 用初始管理员登录，立即改密并绑定 TOTP
# 5. 服务器页添加服务器，ssh 模式点「检测」做真实建连
```

### 13.2 日志

- `start.sh --foreground` / systemd：日志输出到 stdout，由 journald 收集；
- `start.sh` 后台模式：`server/data/logs/packrund.log`；
- 关键日志：启动配置、`[bootstrap]`、`[recover]`、`[hostkey]`、`[task]`、`[metrics]`。

## 14. 常见问题

| 现象 | 原因/处理 |
|---|---|
| release 启动退出「配置安全校验失败」 | 检查 JWT 密钥、管理员口令、`allowed_origins`、`PACKRUN_SSH_INSECURE` |
| 登录总是失败但密码正确 | 已绑 TOTP 时未输入动态口令也会计入失败；5 次锁 5 分钟 |
| 创建 prod 任务返回 1428 | 缺少/错误 step-up OTP；同一码不可重放，等下一个 30 秒 |
| 上传 413 | Nginx `client_max_body_size` 小于请求体，保持 200m |
| 上传中途断开 | 前后端 60s 超时；换稳定网络或减小包体 |
| SSH 报主机指纹拒绝 | 服务器页「检测」首次登记；指纹不匹配确认重建后清除再检测 |
| `zipinfo: command not found` | 安装 `unzip` 包；安全审查强依赖 zipinfo |
| 脚本失败提示 sudo | `runAs` 与登录用户不同时需要 `sudo -n -u` 免密 |
| 发布者看不到自己创建的项目 | 当前实现创建者不会自动写入成员表；由管理员创建并授权成员 |
| 回滚按钮置灰 | 只能选成功且非当前版本批次；包文件必须仍在仓库 |
| 重启后任务全失败 | 设计如此；检查 `[recover]` 与目标目录残留后重发 |
| 改了 `PACKRUN_ADMIN_PASSWORD` 但密码没变 | 只在空库首次初始化生效；忘记密码需数据库运维重置哈希 |
| 审计 IP 是 127.0.0.1 | `trusted_proxies` 与拓扑不符；修正代理配置或清空列表 |
