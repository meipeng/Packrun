# 02 系统架构

## 1. 部署拓扑

```
                    外网浏览器
                        │ HTTPS 443
                        ▼
        ┌──────────────────────────────────┐
        │ Nginx（可选）                     │
        │ TLS 终止 / 反代 / 限流 / 体积限制  │
        └──────────────────┬───────────────┘
                           │ http://127.0.0.1:18080
                           ▼
        ┌──────────────────────────────────┐
        │ frps（可选，公网跳板机）           │
        └──────────────────┬───────────────┘
                           │ frp 隧道
                           ▼
        ┌──────────────────────────────────┐
        │ frpc（可选，中控机）               │
        └──────────────────┬───────────────┘
                           │ http://127.0.0.1:9000
                           ▼
        ┌──────────────────────────────────┐
        │ packrund（Go 中控服务）            │
        │ Gin + SQLite + 包仓库 + 内嵌前端   │
        └──────────────────┬───────────────┘
                           │ SSH（凭据按引用解析）
                           ▼
        ┌──────────────────────────────────┐
        │ 业务服务器 A / B / C …             │
        │ 部署目录 + 前置/后置脚本            │
        └──────────────────────────────────┘
```

关键约束：

- 中控服务默认监听 `0.0.0.0:9000`（直连时用防火墙/安全组限制来源）；由同机 Nginx 终结 TLS 时改为 `127.0.0.1:9000`，公网入口只暴露 443。
- 业务服务器不需要公网可达，只需中控机可通过 SSH 访问。
- Nginx / frp 都是可选的：没有域名与公网穿透需求时，可只运行 `packrund` 单进程。

## 2. 逻辑分层

```
┌─────────────────────────────────────────────────────────────┐
│ 前端 SPA（Vue 3 + Element Plus，构建后嵌入 Go 二进制）        │
│  views / router / stores / api                               │
└──────────────────────────┬──────────────────────────────────┘
                           │ JSON over HTTP /api/v1
┌──────────────────────────▼──────────────────────────────────┐
│ API 层（server/internal/api）                                │
│  router.go       路由与分组                                   │
│  middleware.go   安全头 / CORS / 请求体限制                   │
│  app.go          依赖聚合、鉴权、数据范围、审计、并发闸门      │
│  *_api.go        各领域处理器                                 │
│  task_api.go     任务编排、执行协程、恢复                     │
│  metric_worker.go 后台指标采集                               │
│  static.go       内嵌前端与 SPA 回退                          │
└──────────┬───────────────────────────────┬──────────────────┘
           │                               │
┌──────────▼──────────┐       ┌────────────▼──────────────────┐
│ 领域与执行层         │       │ 认证与安全层                   │
│ deploy/              │       │ auth/                          │
│  Deployer 接口        │       │  bcrypt / JWT / TOTP / 恢复码  │
│  LocalDeployer       │       └────────────┬──────────────────┘
│  SSHDeployer         │                    │
│  Pinger / Prober     │                    │
│  unzip / metrics     │                    │
└──────────┬───────────┘                    │
           │                                │
┌──────────▼────────────────────────────────▼──────────────────┐
│ 配置 / 模型 / 持久化                                          │
│  config/   YAML + 环境变量 + 启动安全校验                     │
│  model/    GORM 实体与状态常量                                │
│  store/    SQLite 打开、AutoMigrate、初始数据                 │
└──────────────────────────────────────────────────────────────┘
```

`deploy` 包不直接访问数据库：主机指纹 TOFU 通过 `HostKeyTrust` 回调由装配层
（`api.TrustHostKeyFunc`）落库并写审计，保证执行层可独立测试与替换。

## 3. Go 包依赖关系

```
cmd/packrund
  ├── internal/config
  ├── internal/store ──→ internal/auth
  │                   └→ internal/config
  │                   └→ internal/model
  ├── internal/deploy ──→ internal/model
  └── internal/api
        ├── internal/auth
        ├── internal/config
        ├── internal/deploy
        ├── internal/model
        └── internal/webui
```

依赖方向是单向的：`config` / `model` / `auth` 不依赖上层；`deploy` 只依赖 `model`；
`api` 负责把所有能力装配起来。

## 4. 启动生命周期

入口：[main.go](../../server/cmd/packrund/main.go)

1. **解析参数**：`-config` 默认 `configs/config.yaml`。
2. **加载配置**：`config.Load` 先取内置默认值，文件存在则 YAML 覆盖，再应用环境变量。
3. **启动安全校验**：`cfg.Validate` 校验运行模式、部署模式、容量阈值、子路径、可信代理；
   非 `debug` 模式强制要求非默认且 ≥32 字符的 JWT 密钥、非默认管理员口令、
   不允许 `allowed_origins` 通配符；`deploy.mode=ssh` 时禁止 `PACKRUN_SSH_INSECURE=1`。
4. **打开存储**：`store.Open` 创建数据目录（`0700`），以 WAL + `busy_timeout=5000`
   打开 SQLite，设置数据库文件 `0600`，执行 `AutoMigrate`。
5. **初始化数据**：`store.Seed` 在无用户时创建管理员；`debug` 模式下额外创建
   `auditor` 演示账号与演示服务器/目录/脚本（仅在对应表为空时）。
6. **中断任务收口**：`api.RecoverInterruptedTasks` 把 `pending/uploading/verifying/executing`
   的任务标记为失败，运行中的步骤标记失败，并写 `task.recover` 审计。
7. **选择执行器**：
   - `deploy.mode=ssh` → `deploy.SSHDeployer`，注入 `StepDelay`、
     `PACKRUN_SSH_INSECURE`、`AutoTrust` 与 `OnTrust`；
   - `deploy.mode=local` → `deploy.LocalDeployer`。
8. **构造应用**：`api.NewApp` 初始化全局并发信号量、可信代理表、服务器闸门表、
   目录锁表、任务取消登记表。
9. **后台指标采集**：仅 `ssh` 模式且执行器实现 `Prober` 时启动，间隔
   `deploy.metrics_interval_seconds`（默认 300 秒，0 关闭）。
10. **构建路由**：`api.NewRouter`；若 `server.base_path != "/"`，用 `api.WithBasePath`
    包裹整个 handler。
11. **启动 HTTP 服务**：`ReadHeaderTimeout=10s`、`ReadTimeout=60s`、
    `WriteTimeout=10m`、`IdleTimeout=120s`、`MaxHeaderBytes=1MB`。

## 5. HTTP 请求生命周期

```
请求
 │
 ├─ gin.Logger / gin.Recovery
 ├─ securityHeaders   基础安全头；/api/* 禁止缓存
 ├─ bodyLimit         非上传请求 1 MiB；上传接口按包配额控制
 ├─ cors              仅白名单 Origin 回显；OPTIONS 直接 204
 │
 ├─ /healthz          直接返回 {"status":"ok"}
 ├─ /api/v1/auth/login 公开
 │
 ├─ /api/v1/*（authed）
 │    └─ authRequired：Bearer JWT 解析 → 用户存在 → tokenVersion 匹配 → 状态 active
 │         ├─ requireRoles(admin)：配置类写操作
 │         ├─ requireRoles(admin, auditor)：审计查询
 │         └─ 业务处理器：角色 + 数据范围 + 业务校验 + 审计
 │
 └─ NoRoute：内嵌静态资源 / SPA 回退 / API 404
```

各业务处理器内部还会做第二层校验，例如：

- `createTask`：审计员拒绝、服务器存在且在当前用户 `serverScope` 内、
  目录属于该服务器、脚本阶段匹配、生产环境 step-up、单用户待执行配额。
- `updateProject`：仅管理员或项目 Owner；成员与发布策略仅管理员。
- `getTask` / `cancelTask`：任务所属服务器必须在用户数据范围内。
- 非管理员读取服务器时 `credentialRef` 脱敏为 `***`。

## 6. 任务执行架构

```
createTask / publishProject / rollbackProject
        │  同步校验 + 落库（pending）
        ▼
   go a.runTask(taskID)        ← 每条任务一个 goroutine
        │
        ├─ lockDirectory(directoryID)     同一目录串行
        ├─ acquireServerGate(serverID)    每台服务器并发上限
        ├─ a.Sem <- struct{}{}            全局并发上限
        ├─ 重新读取任务，确认仍为 pending（排队期间可能被取消）
        ├─ context.WithCancel + Sessions.add（支持取消）
        ├─ 重新加载目录/包/脚本，并校验目录路径快照
        ├─ Deployer.Deploy(ctx, Request{Hooks...})
        │     Hooks.OnStep  → 创建/结束 task_steps
        │     Hooks.OnLog   → 追加步骤输出
        │     Hooks.OnStage → 更新 task.stage / progress / status
        ├─ finishTask(success / failed / canceled)
        │     ├─ 写 task.finish 审计
        │     └─ 项目任务 → settleProjectBatch
        └─ 释放闸门与目录锁
```

并发控制的设计要点：

| 层级 | 实现 | 目的 |
|---|---|---|
| 目录串行 | `App.dirLocks[id] *sync.Mutex` | 避免同目录并发备份/解包互相覆盖 |
| 服务器并发 | `App.gates[serverID] chan struct{}`，容量 `server.maxConcurrent` | 控制单机压力；配置变更后在空闲时重建 |
| 全局并发 | `App.Sem chan struct{}`，容量 `deploy.max_concurrent` | 控制中控机整体负载 |
| 单用户排队 | 统计未终态任务数，`deploy.max_pending_per_user` | 防止资源滥用 |

加锁顺序固定为「目录锁 → 服务器闸门 → 全局闸门」，先等待耗时更长的资源，
避免占着全局槽位空等。

## 7. 单二进制与子路径

- 前端构建产物由 `server/internal/webui/webui.go` 通过 `go:embed all:dist` 嵌入；
  `webui.FS()` 在 `dist/index.html` 不存在时返回 `ok=false`，后端仍可作为纯 API 运行。
- `mountWebUI` 为 History 路由提供 `index.html` 回退，并对 `/assets/` 设置一年
  immutable 缓存；缺失的静态资源不回落 HTML。
- 子路径部署（如 `/packrun`）由两部分协作：
  - `WithBasePath`：剥掉 `/packrun` 前缀后交给 Gin；`/` 与 `/packrun` 301 到
    `/packrun/`；`/healthz` 始终保留在根路径。
  - `injectBaseHref`：服务端读取 `index.html` 并注入 `<base href="/packrun/">`，
    前端 `appBasePath()` 据此推导路由与 API 前缀，无需重新构建。

## 8. 运行时数据布局

默认工作目录为 `server/`（`start.sh` 会 `cd` 到该目录）：

```
server/
├── data/
│   ├── packrun.db          SQLite 主库（含 -wal / -shm）
│   ├── packages/           安装包仓库，按 YYYYMM/<random>.zip|jar 存放
│   ├── sandbox/            local 模式沙箱：<服务器名>/<部署目录>
│   └── logs/packrund.log   start.sh 后台模式日志
└── bin/packrund            单文件产物
```

备份时应同时覆盖数据库与包仓库；凭据文件与 `file:` 引用的私钥不在数据库内，
需要单独保管。

## 9. 扩展点

| 扩展点 | 位置 | 说明 |
|---|---|---|
| 新执行通道 | `deploy.Deployer` | 实现 `Deploy(ctx, Request) error` 即可接入内部 RPC 等；按需实现 `Pinger` / `Prober` |
| 主机信任策略 | `deploy.HostKeyTrust` | 执行层只回调，不依赖数据库 |
| 配置项 | `internal/config` | 新增字段后同步 `defaults()`、`Validate()`、`applyEnv()` |
| 持久化 | `internal/store` | 当前 SQLite；替换 PostgreSQL 只需改 `Open` 与 DSN |
| 前端页面 | `web/src/views` + `router/index.ts` + `AppLayout.vue` 菜单 | 新增路由、菜单项与 API 模块 |
| 静态托管 | `internal/api/static.go` | 可替换为独立 Nginx 托管，Go 侧保持纯 API |
