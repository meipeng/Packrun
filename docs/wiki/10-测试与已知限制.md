# 10 测试与已知限制

## 1. 测试布局

后端测试全部位于 `server/internal/**/**_test.go`，使用：

- 内存 SQLite（`file:...?mode=memory&cache=shared`）+ `AutoMigrate`；
- `gin.TestMode` + `httptest` 直接调用路由；
- 内存包级 `failureCounter` 在每个用例前重置，避免限流状态串扰；
- SSH 测试使用进程内 fake SSH 服务端，不依赖真实机器。

## 2. 运行测试

```bash
cd server
go test ./...                 # 全部后端测试
go test ./internal/api -v     # 单个包
go test -run TestLogin ./internal/api -v
go test -race ./...           # 竞态检查（耗时更长）
go vet ./...
```

依赖漏洞：

```bash
cd server
go run golang.org/x/vuln/cmd/govulncheck@latest ./...

cd web
pnpm audit --prod
```

前端当前没有单元测试或 E2E 测试，可用静态检查与构建验证：

```bash
cd web
pnpm type-check
pnpm build
```

## 3. 已知限制

以下为当前代码的真实行为（部分与界面文案存在差异），使用与排障时需注意：

| # | 限制 | 说明 |
|---|---|---|
| 1 | zip 部署默认仍不删除多余旧文件 | 「仅新增」已对 zip 生效（包内文件与目录现有文件冲突即拒绝解压）；开启目录「干净替换」后按发布差异清单清理包内不存在的旧文件（仅限部署目录内，文件数上限 5 万） |
| 2 | 发布者自建项目对自己不可见 | `createProject` 不会把创建者写入 `project_members`，而 `listProjects` 对非管理员只返回成员项目。规避：由管理员创建项目并授权成员 |
| 3 | 自动恢复只覆盖「目标目录」 | 失败后恢复的是部署目录本身；脚本产生的副作用（重启服务、写 `/etc`、建软链）不会被撤销，需脚本自身可重入 |
| 4 | 项目回滚依赖历史包文件 | 超出 `package_keep_releases` 窗口的包会被 GC 回收，被回收批次的回滚会失败；需要长期保留请调大窗口 |
| 5 | 中断任务需人工恢复 | 服务重启后排队任务自动重新入队；已开始执行的进入「待恢复」，需人工「继续执行」（跳过已完成步骤）或「标记失败」 |
| 6 | 健康检查不探测目标机 | `/healthz` 只检查本机数据库、包目录与磁盘；SSH 凭据与目标机连通性以「服务器 → 检测」为准 |
| 7 | local 模式无目标机语义 | 检测恒成功；脚本只回显；不能验证脚本语法、systemd、目标机依赖 |
| 8 | 部署目录「属主」字段不生效 | 不会自动 `chown`，目标机权限需事先就绪 |
| 9 | 项目发布策略改写全局目录策略 | 项目设置中的备份/覆盖/保留版本会写入全部绑定目录本身 |
| 10 | 审计员可执行连通性检测 | `ping`/`probe`/`hostkey probe` 在普通认证路由下，审计员在范围内可调用并更新服务器状态 |
| 11 | 单步日志有上限 | 头部 8KB + 尾部 24KB，中间丢弃并标注省略量；过期步骤正文按 `task_log_retention_days` 清理 |
| 12 | 单用户任务配额存在竞态 | `checkPendingTaskLimit` 先查后写，并发请求可能短窗口轻微超限 |
| 13 | 项目 code 唯一性存在竞态 | 模型无唯一索引，仅应用层查询；并发创建理论上可产生重复 |
| 14 | 无版本化迁移 | 启动 `AutoMigrate`，没有迁移版本号、降级脚本；升级前备份是唯一回退手段 |
| 15 | 无 OpenAPI/Swagger | 接口以本文与源码为准，没有自动生成的机器可读契约 |
| 16 | 进程内状态 | 登录/step-up 限流、任务取消登记、并发闸门、目录锁、上传幂等令牌均为单进程内存状态；不支持多实例同时执行任务（告警去重已落库） |
| 17 | 证书告警按周提醒 | 证书到期去重状态按 7 天滚动清理：证书持续未处理时每周重复提醒一次 |
| 18 | 审计写入失败不影响主流程 | `auditAs` 忽略数据库错误，极端情况下可能缺少审计记录 |
| 19 | 凭据引用可见性 | 管理员可见 `credentialRef`（引用而非明文）；非管理员为 `***` |

## 4. 设计权衡

| 决策 | 原因 | 代价 |
|---|---|---|
| SQLite + 纯 Go 驱动 | 单机中控、零外部依赖、免 CGO 交叉编译 | 并发写入有限；多实例不可用 |
| 进程内任务 goroutine | 实现简单，状态直接回写数据库 | 重启丢任务；取消/并发状态不跨进程 |
| `AutoMigrate` | 单二进制启动即可用 | 无版本化迁移与降级 |
| 凭据只存引用 | 数据库泄露不等于凭据泄露 | 部署时依赖环境变量/文件存在 |
| TOFU 主机指纹 | 无需预置 known_hosts，首次可用 | 首次连接仍存在信任窗口；需人工处理重建 |
| 单二进制内嵌前端 | 交付简单，前后端版本天然一致 | 前端更新必须重新构建二进制 |
| local 模式不执行脚本 | 避免开发机被任意命令注入 | 无法在本地验证真实脚本效果 |
| 项目批次全部成功才推进版本 | 版本语义严格 | 部分失败时项目版本保持旧值，需要人工判断 |

## 5. 建议的改进方向

按收益/成本排序：

1. **把项目创建者加入成员表**，修复「自己建的项目看不到」；
2. **版本化迁移**（如 `golang-migrate`）与升级/降级说明；
3. **分布式锁/队列**：若需要多实例，需把目录锁、服务器闸门、取消登记外置；
4. **项目 code 唯一索引**与并发创建保护；
5. **OpenAPI 生成**，减少前后端契约漂移；
6. **审计防篡改**（哈希链或外部日志）；
7. **前端单元/E2E 测试**，覆盖登录、部署向导、项目发布关键路径。

> 已收口项（包仓库 GC、上传超时放宽与幂等、任务持久化续跑、脚本快照、告警去重落库、
> 干净替换与发布差异清单）详见仓库 `docs/ROADMAP.md`。

## 6. 排障入口

| 问题 | 首先查看 |
|---|---|
| 服务启动失败 | `journalctl -u packrund` / `server/data/logs/packrund.log`；配置安全校验错误信息会指出字段 |
| 登录/OTP 异常 | 审计页 `auth.*`；服务端 `last_otp_step`；确认时间同步 |
| SSH 连接失败 | 服务器页「检测」；凭据引用是否可解析；主机指纹是否匹配；目标机 SSH 端口 |
| zip 解包失败 | 目标机是否有 `unzip`/`zipinfo`；包内是否有绝对路径/`..`/符号链接；条目数与体积 |
| 任务一直 pending | 全局/服务器并发是否占满；同目录是否有长任务；单用户配额；服务是否刚重启 |
| 任务失败但不知道原因 | 任务详情步骤日志；`task.finish` 审计；执行器返回的错误信息 |
| 项目版本不推进 | 批次是否全部成功；是否有取消/失败任务；`settleProjectBatch` 只处理全成功批次 |
| 页面 404 / 跳转循环 | `server.base_path` 与 Nginx `location`、`proxy_pass` 是否一致；`proxy_pass` 不能带尾斜杠 |
| 审计 IP 不正确 | `server.trusted_proxies`；代理层是否正确写入 `X-Forwarded-For` |
