# 07 认证授权与安全

## 1. 安全目标与边界

Packrun 的安全边界是「中控机」：

- 中控机持有数据库、包仓库、SSH 凭据引用与主机指纹；
- 业务服务器只需中控机可达，不需要对公网暴露；
- 浏览器只与中控服务通信，不直接接触业务服务器；
- 生产部署属于高危操作，要求动态口令再认证。

系统假设中控机本身可信；数据库文件、环境变量、`file:` 引用的私钥需要按敏感资产保护。

## 2. 认证

### 2.1 第一因子：口令

- 存储：bcrypt（`DefaultCost`），字段 `users.password_hash`；
- 校验：`auth.VerifyPassword`；
- 账号不存在时仍执行一次 dummy bcrypt，避免通过响应时间枚举账号；
- 登录错误统一提示「账号或密码错误」，不区分账号不存在/禁用/口令错误；
- 新口令至少 8 位。

### 2.2 会话：JWT

`auth.IssueToken` 生成 HS256 JWT：

```json
{
  "uid": 1,
  "usr": "admin",
  "rol": "admin",
  "ver": 3,
  "sub": "1",
  "iss": "packrun",
  "iat": 1700000000,
  "exp": 1700028800
}
```

- `auth.ParseToken` 只接受 `HS256` 且校验 `iss=packrun`；
- TTL 由 `auth.token_ttl_minutes` 控制，默认 480 分钟；
- `ver` 与数据库 `users.token_version` 比对，不一致立即 401；
- 用户状态非 `active` → 403。

令牌吊销场景：

| 操作 | token_version |
|---|---|
| 修改口令 | +1 |
| 管理员重置口令 | +1 |
| 角色变化 | +1 |
| `serverScope` 变化 | +1 |
| 状态变化 | +1 |

历史数据 `token_version<=0` 按 1 处理。

### 2.3 登录流程与失败限制

入口：`App.login`（[auth_api.go](../../server/internal/api/auth_api.go)）。

```
解析 username/password/otp
 ├─ 账号或 IP 已锁定 → 429
 ├─ 查询用户
 │    └─ 不存在 → dummy bcrypt → 记失败（账号 + IP）→ 401
 ├─ 状态非 active → 记失败 → 401
 ├─ 口令错误 → 记失败 → 401
 ├─ 已绑定 OTP：
 │    ├─ otp 为空 → 记失败 → 401 code 1428
 │    ├─ TOTP 校验通过且时间步进未被消费 → 通过
 │    └─ 否则尝试恢复码 → 通过则 usedRecovery=true
 ├─ token_version<=0 → 先落为 1
 ├─ 签发 JWT
 ├─ 更新 last_login_at
 ├─ 清零账号与 IP 失败计数
 └─ 写 auth.login 审计
```

失败限制：

| 维度 | 阈值 | 锁定时长 |
|---|---|---|
| 单账号 | 5 次 | 5 分钟 |
| 单 IP | 30 次 | 5 分钟 |
| step-up OTP | 5 次 | 5 分钟 |

计数器特性：

- 进程内内存 `failureCounter`，按 key 记录次数与解锁时间；
- 条目 10 分钟未更新会被惰性清理；map 超过 10000 条时淘汰最旧约 10%；
- 服务重启后计数清零；多实例部署不共享计数。

### 2.4 第二因子：TOTP

- 种子：20 字节随机数，base32 无填充，保存在 `users.otp_secret`；
- 算法：HMAC-SHA1，6 位，周期 30 秒，允许 ±1 个时间窗；
- 绑定：`otp/setup` 生成种子 → 认证器扫码或手动录入 → `otp/activate` 输入当前口令；
- 换绑：`otp/rebind`（旧口令校验）→ 新种子 → `otp/activate`（新口令确认），
  待确认种子 10 分钟过期；确认前旧口令仍有效；
- 解绑：`otp/disable` 需当前口令，解绑后删除全部恢复码；
- 一次性：`consumeOTPStep` 原子更新 `last_otp_step`，同一个时间步进不能被重复使用。

`otpauth` 链接参数：`issuer`、`secret`、`algorithm=SHA1`、`digits=6`、`period=30`。

### 2.5 登录恢复码

- 绑定/换绑成功时生成 10 枚一次性恢复码；
- 格式 `XXXX-XXXX-XXXX-XXXX`，归一化后 16 个 base32 字符（80-bit 熵）；
- 数据库只保存 SHA256 哈希；
- 登录时 TOTP 不可用，可把恢复码填入 OTP 字段；
- 恢复码使用后立即标记 `used_at`，不能重复使用；
- 重新生成会删除全部旧码并发放新码，旧码立即失效；
- 恢复码为空输入不会触发恢复码校验（OTP 为空直接返回 1428）。

### 2.6 高危操作再认证（step-up）

以下操作需要当前 TOTP：

| 操作 | 校验函数 | 失败返回 |
|---|---|---|
| 生产环境创建部署任务 | `verifyStepUpOTP` | 401 code 1428 |
| 生产环境项目发布 | `verifyStepUpOTP` | 401 code 1428 |
| 生产环境项目回滚 | `verifyStepUpOTP` | 401 code 1428 |
| 修改口令（已绑定 OTP） | `verifyOTPWithLimit` | 401 code 1003 |
| OTP 换绑/解绑/恢复码重生成 | `verifyOTPWithLimit` | 400 |

step-up 要求账号**已绑定 OTP**；未绑定账号无法在生产环境发起部署。
`verifyOTPWithLimit` 叠加 5 次失败 / 5 分钟锁定。

## 3. 授权

### 3.1 角色

| 角色 | 能力 |
|---|---|
| `admin` | 全部；唯一可管理服务器/目录/脚本/用户与项目成员/策略的角色 |
| `deployer` | 在授权范围内部署、发布、回滚、取消任务、上传包；可创建项目，但项目列表只显示其作为成员的项目（当前实现创建者不会自动成为成员，见 [10-测试与已知限制](10-测试与已知限制.md)） |
| `auditor` | 只读；可查看服务器/任务/项目/审计；不能部署、取消、上传包、创建/删除项目。当前实现允许对范围内服务器执行 ping/probe/主机指纹采集（会更新状态并写审计） |

路由层只做了粗粒度分组（admin、admin+auditor），处理器内部还有细粒度校验。

### 3.2 服务器数据范围 `serverScope`

- `users.server_scope` 为 `*`、空或用户是管理员 → 不受限；
- 否则为逗号分隔的服务器 ID；
- `scopeServerIDs` 解析范围，`checkServerScope` 校验单个服务器，
  `applyServerScope` 给列表查询追加 `WHERE server_id IN (...)`；
- 无可用 ID 时追加 `1 = 0`，返回空集而不是全量。

受影响资源：服务器、目录、任务、概览统计、项目目录绑定校验、发布前置校验。

### 3.3 项目授权

| 操作 | 规则 |
|---|---|
| 查看项目 | 管理员或 `project_members` 中存在该用户 |
| 修改项目名称/描述/目录绑定 | 管理员或项目 Owner |
| 修改成员/发布策略 | 仅管理员 |
| 发布/回滚 | 管理员或项目成员，且目录服务器在 `serverScope` |
| 创建项目 | 非审计员 |
| 删除项目 | 非审计员且管理员或 Owner |

### 3.4 凭据脱敏

- 数据库只存 `credential_ref`（`env:` / `file:`）；
- 非管理员读取服务器时 `credentialRef` 被替换为 `***`；
- 管理员可见原始引用，但仍不会返回凭据内容本身；
- 凭据内容在 SSH 连接时由 `ResolveCredential` 运行时解析。

## 4. 审计

`audit_logs` 记录：

- 操作者 ID / 账号（系统事件为 `system`）；
- 动作（如 `task.create`、`project.publish`）；
- 目标（服务器:目录、项目名、任务号）；
- 结果 `ok/fail`；
- 真实客户端 IP；
- 任务号；
- 动态口令是否通过；
- 细节文本；
- 时间。

覆盖范围：登录成功/失败、恢复码登录、改密、OTP 绑定/换绑/解绑、恢复码重生成、
服务器/目录/脚本/用户配置变更、包上传、任务创建/结束/取消/重启收口、
项目创建/修改/删除/发布/回滚、主机指纹自动登记/检测/清除、服务器 ping/probe。

审计写入失败不影响主流程（`auditAs` 忽略错误）。

## 5. 传输与 HTTP 安全

| 控制 | 实现 |
|---|---|
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、`Cross-Origin-Resource-Policy: same-origin` |
| API 缓存 | `/api/*` 加 `Cache-Control: no-store` |
| CSP | 单二进制托管前端时注入 CSP：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; ...` |
| CORS | 仅白名单 Origin 回显；精确匹配才允许 credentials；通配来源不发放凭据 |
| 请求体限制 | 非上传请求 1 MiB；上传按 200MB 与包仓库配额 |
| Multipart 内存 | `MaxMultipartMemory = 32 MiB` |
| 服务器超时 | `ReadHeaderTimeout=10s`、`ReadTimeout=60s`、`WriteTimeout=10m`、`IdleTimeout=120s`、`MaxHeaderBytes=1MB` |
| 真实 IP | 仅可信代理网段才采信 `X-Forwarded-For` / `X-Real-IP` |

生产环境建议由 Nginx 额外提供 TLS 1.2/1.3、HSTS、登录接口独立限流与安全头，
样例见 [deploy/nginx.conf.example](../../deploy/nginx.conf.example)。

## 6. 凭据与 SSH 信任

### 6.1 凭据引用

| 形式 | 示例 | 解析 |
|---|---|---|
| 环境变量 | `env:PROD_SSH_PASSWORD` | 读取进程环境变量 |
| 文件 | `file:~/.ssh/id_ed25519` | 读取文件内容，支持 `~/` |

- 服务器创建/修改时强制要求 `env:` 或 `file:` 前缀，拒绝明文；
- key 类型凭据自检会验证私钥可解析且不带 passphrase；
- 带 passphrase 的私钥无法在中控无交互流程中使用。

### 6.2 主机指纹 TOFU

- 服务器首次 SSH 连接时，如果库中无指纹且 `auto_trust_hostkey=true`，
  自动登记公钥算法、base64 公钥与 SHA256 指纹，并写审计；
- 之后每次连接严格比对指纹与算法，不一致即拒绝；
- 服务器重建后需在「服务器 → 指纹」清除，下次连接重新信任；
- `auto_trust_hostkey=false` 时未登记指纹的服务器回退 `~/.ssh/known_hosts`；
- `PACKRUN_SSH_INSECURE=1` 仅开发环境可用，非 debug 模式启动校验会直接拒绝。

## 7. 文件与解包安全

| 风险 | 防护 |
|---|---|
| 恶意包扩展名 | 读取文件头 `PK\x03\x04` 校验真实格式 |
| 包名路径注入 | `filepath.Base` + 控制字符替换 |
| 包仓库占满 | 上传前按声明大小预检，写入后按实际占用复核 |
| zip 路径穿越 | 本地拒绝绝对路径/`..`/越界；SSH 用 `unzip -Z1` 审查 |
| 符号链接逃逸 | 本地拒绝 zip 内符号链接并校验父目录真实路径；SSH 用 `zipinfo` 拒绝 |
| 解压炸弹 | 条目数 ≤20000；解压字节 ≤目录阈值或 1GB；SSH 额外 `ulimit -f` |
| 目录被占满 | 部署前与解压后两次 `du` 阈值检查 |
| 覆盖策略 | `allowOverwrite=false` 时单文件制品目标存在即拒绝 |
| 远程命令注入 | 路径参数统一 `shellQuote`；脚本内容 base64 传输 |
| 脚本提权 | `sudo -n`（无交互），失败即脚本失败 |

## 8. 启动时 fail-closed

非 `debug` 模式下，以下任一不满足服务拒绝启动：

- `auth.jwt_secret` 非空、非默认占位值、≥32 字符；
- `bootstrap.admin_password` 非空且非默认 `Admin@12345`；
- `server.allowed_origins` 不含 `*`；
- `deploy.mode=ssh` 时 `PACKRUN_SSH_INSECURE` 未设置为 `1`；
- `server.mode` 只能是 `debug/release/test`；
- `deploy.mode` 只能是 `local/ssh`；
- `storage.max_total_mb`、`deploy.max_pending_per_user`、`deploy.metrics_interval_seconds` 非负；
- `server.trusted_proxies` 每项为合法 CIDR 或 IP；
- `server.base_path` 格式合法。

## 9. 生产安全检查清单

1. `server.mode=release`，通过环境变量提供强 JWT 密钥与管理员口令；
2. 首次登录后立即改密并绑定 TOTP；
3. 删除或改密 `auditor` 演示账号（该账号只在 debug 创建）；
4. 核对 `server.trusted_proxies`：只有 Nginx/frpc 与中控同机且 18080 未对公网开放时
   才保留回环地址，否则清空，避免伪造 `X-Forwarded-For`；
5. Nginx 启用 TLS 1.2/1.3、HSTS、CSP、安全头；`client_max_body_size 200m`；
   登录接口独立限流；
6. frps `proxyBindAddr` 保持回环，18080 只允许 Nginx 访问；
7. 中控 `data/`（SQLite、包仓库）纳入备份；SSH 私钥与环境变量单独保管；
8. 定期复跑 `govulncheck` 与 `pnpm audit --prod`；
9. 限制中控机登录权限与文件权限（数据目录 `0700`、数据库 `0600`）；
10. 关注失败任务与审计日志，定期清理历史数据。

## 10. 已知限制与注意点

| 项 | 说明 |
|---|---|
| 进程内限流 | 登录与 step-up 失败计数在内存中，重启清零；多实例不共享 |
| 单实例假设 | 任务取消登记、并发闸门、目录锁都是进程内状态，不支持多实例同时执行任务 |
| OTP 种子明文 | `users.otp_secret` 在数据库中为明文 base32；数据库泄露等同 TOTP 泄露 |
| 恢复码哈希 | SHA256 无盐，但 80-bit 随机熵足够；依赖数据库访问控制 |
| 审计不可篡改 | 审计日志无签名/链式校验，拥有数据库写权限者可修改 |
| 包可见性 | 所有登录用户都能列出全部安装包，未按项目或范围隔离 |
| 项目 code 唯一性 | 应用层查询保证，模型无唯一索引，并发创建存在理论竞态 |
| 检测权限 | 审计员可对范围内服务器执行 ping/probe/hostkey 采集（只读语义，但会写状态与审计） |
| 本地模式 | 脚本只回显不执行，不能用于验证脚本真实效果 |
| 取消粒度 | 解包/上传等不可中断点需等待当前操作返回；可能留下临时文件 |
| 无自动回滚 | 任务失败不会自动恢复 `.bak-*`，需人工处理 |
| 依赖漏洞 | 需定期执行 `go run golang.org/x/vuln/cmd/govulncheck@latest ./...` 与 `pnpm audit --prod` |

## 11. 安全验证命令

```bash
# 后端测试（包含认证、越权、上传、解包、恢复等安全回归）
cd server
go test ./...

# 依赖漏洞
go run golang.org/x/vuln/cmd/govulncheck@latest ./...

# 前端生产依赖审计
cd web
pnpm audit --prod
```
