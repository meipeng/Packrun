# Packrun 技术选型与客户端设计

> 本文承接《开发文档计划》，把"引入开发框架"和"开发浏览器端控制台"落成可执行的工程决策。
> 架构前提：**方案 2 —— Go 部署服务部署在中控机，纳管多台业务服务器**。

## 1. 链路定稿

```
外网浏览器
   │  HTTPS 443（域名）
   ▼
Nginx（TLS 终止、反向代理、限流、上传体积限制、真实 IP 透传）
   │  http://frpc / 内网回源
   ▼
frp（frps 公网入口 → frpc 内网侧）
   │
   ▼
Go 部署服务（中控机，核心服务 + SQLite + 包仓库）
   │  SSH（执行通道，凭据按引用解析，不落明文）
   ▼
业务服务器 A / B / C …（指定部署目录 + 远程脚本）
```

中控机是唯一对外暴露点；业务服务器不需要对公网开放。执行通道先实现 SSH，
`内部 RPC` 作为同一 `Deployer` 接口的第二实现预留，切换只改配置不改上层代码。

## 2. 框架选型

| 层 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 语言 | Go 1.22+ | 单二进制交付，中控机部署无运行时依赖 | — |
| HTTP 框架 | Gin | 中间件模型清晰，团队上手成本最低，路由分组贴合 `/api/v1` 分域 | chi、Echo |
| ORM | GORM + 纯 Go SQLite 驱动 | 免 CGO 交叉编译；单机中控场景不需要独立数据库 | 手写 SQL、PostgreSQL |
| 配置 | YAML + 环境变量覆盖 | 中控机单文件配置，敏感项走环境变量 | Viper |
| 认证 | bcrypt + JWT(HS256) + TOTP | 第一因子口令、第二因子动态口令、无状态会话 | Session + Redis |
| 执行通道 | golang.org/x/crypto/ssh | 复用系统 SSH 语义，凭据按引用解析 | 内部 RPC（预留） |
| 前端 | Vue 3 + TypeScript + Vite | 与现有 Vue 技术栈一致，组合式 API 便于抽逻辑 | React |
| UI | Element Plus | 表格/表单/步骤条/时间线齐全，管理台开发最快 | Naive UI、Ant Design Vue |
| 状态/路由 | Pinia + Vue Router | 官方标配 | — |
| 请求 | axios（统一拦截器） | 统一注入令牌、统一解包错误码 | fetch 封装 |

> 选型原则：**中控机单机可跑、无外部强依赖**。数据库、包仓库、日志都落在中控机本地目录，
> 后续要换 PostgreSQL 只改 `store` 层。

## 3. 工程结构

```
Packrun/
├── docs/                     设计文档
├── server/                   Go 中控服务
│   ├── cmd/packrund/         入口
│   ├── configs/              配置样例
│   └── internal/
│       ├── config/           配置加载
│       ├── model/            实体定义
│       ├── store/            持久化与初始化
│       ├── auth/             口令、JWT、TOTP
│       ├── deploy/           执行器（local / ssh）

```

## 4. 浏览器端设计

### 4.1 页面结构

| 路由 | 页面 | 关键内容 |
|---|---|---|
| `/login` | 登录 | 账号 + 口令 + 动态口令（缺动态口令时二次提示） |
| `/` | 概览 | 服务器在线数、今日任务、失败率、最近任务 |
| `/servers` | 服务器管理 | 列表、环境下标签、新增/编辑抽屉、连通性检测 |
| `/deploy` | 部署向导 | 选服务器 → 选目录 → 上传包 → 脚本与确认 → 执行 |
| `/tasks` | 任务列表 | 状态筛选、进度、操作人、耗时 |
| `/tasks/:id` | 任务详情 | 步骤时间线、阶段日志、失败原因 |
| `/scripts` | 脚本管理 | 前置/后置脚本、超时、执行身份、版本 |
| `/audit` | 审计日志 | 操作者、真实 IP、动作、结果、动态口令校验 |
| `/profile` | 个人设置 | 动态口令绑定 / 换绑 / 恢复码 |

### 4.2 部署向导交互

1. **选服务器**：卡片式，展示环境标签与在线状态，prod 环境红色边框提示。
2. **选目录**：联动该服务器已配置目录；展示覆盖策略、备份策略、空间阈值。
3. **上传包**：`el-upload` 手动上传，前端校验扩展名（zip/jar）与大小，展示上传进度与 SHA256。
4. **脚本与确认**：选择后置脚本、预览摘要；`prod` 环境强制弹出动态口令输入框（step-up 再认证）。
5. **执行**：拿到任务号跳转详情页，2 秒轮询状态直至终态。

### 4.3 状态与错误处理

- `stores/auth.ts` 保存令牌与用户信息，路由守卫拦截未登录。
- axios 拦截器统一处理 `401`（跳登录）、`403`（提示越权）、`428`（需要动态口令）。
- 任务详情页按状态机渲染：`pending → uploading → verifying → executing → success / failed`。

## 5. 后端接口约定

统一响应：`{"code":0,"message":"ok","data":...}`；错误码分段：
`1xxx` 认证、`2xxx` 权限、`3xxx` 参数与配置、`4xxx` 部署执行、`5xxx` 系统。

| 域 | 接口 |
|---|---|
| 认证 | `POST /api/v1/auth/login`、`GET /api/v1/auth/me`、`POST /api/v1/auth/otp/setup`、`POST /api/v1/auth/otp/activate` |
| 服务器 | `GET/POST /api/v1/servers`、`PUT/DELETE /api/v1/servers/:id`、`POST /api/v1/servers/:id/ping` |
| 目录 | `GET /api/v1/directories?serverId=`、`POST/PUT/DELETE /api/v1/directories` |
| 脚本 | `GET/POST /api/v1/scripts`、`PUT/DELETE /api/v1/scripts/:id` |
| 包 | `POST /api/v1/packages`（multipart）、`GET /api/v1/packages` |
| 任务 | `POST /api/v1/tasks`、`GET /api/v1/tasks`、`GET /api/v1/tasks/:id`、`POST /api/v1/tasks/:id/cancel` |
| 审计 | `GET /api/v1/audit` |
| 健康 | `GET /healthz` |

## 6. 安全约束在代码中的落点

- 凭据：`servers.credential_ref` 只存引用（`env:PROD_SSH_PASSWORD` / `file:~/.ssh/id_ed25519`），运行时解析。
- 高危再认证：`prod` 环境创建任务必须携带 `X-OTP`，校验失败返回 `1428`。
- 路径安全：部署目录强制绝对路径，拒绝 `..` 与软链逃逸。
- 审计：登录、配置变更、任务创建与终态全部落 `audit_logs`，含真实 IP 与动态口令校验结果。
